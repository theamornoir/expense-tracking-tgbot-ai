# AI Expense Tracking Bot

Сервис учёта семейных расходов: Telegram-бот с ИИ-агентом + веб-панель для главы семьи. Один Go-монолит, один бинарник, один `docker compose up`.

## Быстрый старт

```bash
docker compose up --build
```

- Веб-панель: `http://localhost:8080`
- Telegram-бот: long polling, отвечает сообщениям
- БД инициализируется автоматически (миграции при старте)

## Режим моков (MOCK_LLM)

Чтобы продемонстрировать бота без реальных расходов на LLM, включите мок-режим. В этом режиме агент не ходит в настоящий API, а отдаёт готовые ответы из карты `MockResponses` (`internal/llm/client.go`) по точному совпадению текста сообщения.

Включить моки:

```bash
# .env
MOCK_LLM=true
```

Выключить (боевой режим с настоящей LLM):

```bash
# .env
MOCK_LLM=false
```

После изменения `.env` пересоберите контейнер:

```bash
docker compose up --build -d
```

Проверить режим можно в логах:

```bash
docker compose logs -f app
# в боевом режиме:  "starting in normal mode"  model=gpt-4o-mini
# в мок-режиме:      "starting in mock mode"    MOCK_LLM=true
```

Ключевой момент: в мок-режиме ответы отдаются только при точном совпадении строки. Сообщение должно быть написано так же, как ключ в `MockResponses` (например, `кофе 350`, `покажи траты`, `удали такси`). Любое другое сообщение получит общий ответ `Не понял. Попробуйте снова.`

Для проверки реального tool calling (создание/чтение/изменение/удаление трат через инструменты) переключитесь на `MOCK_LLM=false` и укажите рабочие `LLM_API_KEY` / `LLM_BASE_URL`.

## Добавление пользователей

Список пользователей задаётся в `.env` через переменную `ALLOWED_USER_IDS` — это allow list (белый список). Только эти ID могут пользоваться ботом, и только они попадут в выпадающий фильтр веб-панели.

```bash
# .env — несколько ID через запятую, без пробелов
ALLOWED_USER_IDS=899742161,111222333,444555666
```

Как узнать свой Telegram ID:

1. Напишите боту @userinfobot - он сразу пришлёт ваш numeric ID.

Добавить пользователя = дописать его ID в `ALLOWED_USER_IDS` и перезапустить приложение:

```bash
docker compose up --build -d
```

Важно:

- Пустой список запрещён — `Load()` вернёт ошибку `at least one user id required`, приложение не стартует.
- ID, которого нет в списке, получит от бота: `Извините, у вас нет доступа к боту.`
- При попытке создать трату через REST с `user_id` не из списка вернётся `400 user not allowed`.
- Сами ID в панели редактировать нельзя — это защита: LLM не может подставить чужой `user_id`, а в allow list можно попасть только через `.env`.

## Работа с веб-панелью

Откройте http://localhost:8080 после `docker compose up --build -d`.

> Панель без авторизации по условию ТЗ — доступна всем, кто знает адрес. 

### Добавление траты

1. Слева заполните форму:
   - Пользователь — выпадающий список (заполняется из `ALLOWED_USER_IDS`).
   - Сумма — в рублях, можно с копейками (`350`, `89.50`). Должна быть больше нуля.
   - Категория — еда, транспорт, жильё, развлечения, здоровье, покупки, другое.
   - Дата — формат `YYYY-MM-DD` 
   - Комментарий — необязательно.
2. Нажмите Добавить.
3. Под формой появится подтверждение, а строка — в таблице справа.

### Просмотр и фильтры

- Пользователь — показать траты только одного человека.
- с / по — диапазон дат (`spent_at`).
- Категория — фильтр по категории.
- Строка Итого справа сверху пересчитывается под текущий фильтр.
- Если по фильтру записей нет — появится `Нет трат за выбранный период.`

Фильтры применяются автоматически при изменении любого поля (`onchange` → `loadExpenses()`).

### Редактирование и удаление

- Ред. — открывает модалку: сумма, категория, дата, комментарий. Поле ID пользователя только для чтения. Сохранение → `PUT /api/expenses/{id}`.
- Уд. — удаляет строку, backend вернёт `204`. Отменить нельзя.

### Синхронизация с ботом

Бот и панель работают с одной БД. Чтобы увидеть, что бот реально сохранил трату:

1. Отправьте боту `кофе 350`.
2. Обновите страницу панели (F5 / ⌘R).
3. Трата появится в таблице (при нужном фильтре — проверьте, что пользователь и дата совпадают).

При смене фильтров и после каждого изменения обновляйте страницу жёстким рефрешем (⌘⇧R), чтобы не было кеша.

## Работа с Telegram-ботом

Бот работает через long polling — ни домен, ни SSL, ни открытый порт не нужны. Доступ получают только пользователи из `ALLOWED_USER_IDS`.

### Быстрый сценарий (MOCK_LLM=true)

| Вы пишете | Бот отвечает |
|---|---|
| `привет` | Привет! Я бот для учёта семейных расходов. |
| `кофе 350` | Трата добавлена успешно. |
| `покажи траты` | Ваш список траты: 3 записи, сумма 15000 руб. |
| `покажи траты за неделю` | Все траты за неделю: 2500 руб. |
| `сколько потратил на еду в этом месяце` | Эта неделя: 3000 руб. |
| `последнее было не 350, а 450` | Трата обновлена на 450 руб. |
| `удали такси` | Трата удалена. |
| `удали все` | Не можете удалить все траты. Уточните, что именно удалить. |
| незнакомое сообщение | Не понял. Попробуйте снова. |

В мок-режиме ответ привязан к **точному** совпадению строки — напишите пример как в таблице.

### Сценарий с настоящей LLM (MOCK_LLM=false)

Здесь работает tool calling — бот сам выбирает инструмент и аргументы:

| Вы пишете | Что происходит |
|---|---|
| `кофе 350` | LLM → tool `add_expense{category:"еда", amount:350}` → трата сохранена |
| `вчера потратил на такси 600` | сумма и категория извлечены LLM, дата — «вчера» относительно системного промпта с текущей датой |
| `покажи траты за неделю` | tool `list_expenses{from:..., to:...}` → список |
| `последнее было не 350, а 450` | tool `list_expenses{sort:"created", limit:1}` → tool `update_expense{id, amount:450}` |
| `удали такси`, а такси несколько | бот переспрашивает, какую именно удалить, и ждёт ID |
| `удали все` | отказ: нельзя удалить все траты разом, нужно уточнить |

### Полезные подсказки

- Последняя трата» = последняя по дате создания (`sort=created&limit=1`), а не последняя по дате покупки.
- «Вчера» / «на этой неделе» считаются от текущей даты в часовом поясе `APP_TIMEZONE` (по умолчанию `Europe/Moscow`) — дата зашита в system prompt.
- Бот ограничена 5 итерациями за одно сообщение (`maxIterations = 5`). Если LLM упорно ошибается, пользователь получит понятный текст, а не зависание.
- Ошибки инструментов (например, `amount must be greater than zero`) возвращаются LLM как tool result — агент исправляется и повторяет вызов сам.
- История диалогов — последние 10 сообщений на пользователя, хранится в памяти процесса (сбрасывается при рестарте контейнера).
- Сообщения одного пользователя обрабатываются **последовательно** (per-user lock), параллельных вставок в одну историю не бывает.

### Если бот молчит

1. Проверьте, что ваш `user_id` есть в `ALLOWED_USER_IDS` и `.env` перечитан (нужен `docker compose up --build -d`).
2. Смотрите логи: `docker compose logs -f app`.
3. Нет `Telegram bot polling started` → проблема с `TELEGRAM_TOKEN`.
4. Ответа нет при `MOCK_LLM=false` → проверьте `LLM_API_KEY` / `LLM_BASE_URL`; после 3 ретраев пользователь увидит `Извините, не удалось связаться с ассистентом. Попробуйте позже.`


## REST API (веб-панель)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/expenses` | Список трат. Фильтры: `user_id`, `from`, `to`, `category`, `limit`, `sort` |
| POST | `/api/expenses` | Создать трату |
| PUT | `/api/expenses/{id}` | Редактировать трату |
| DELETE | `/api/expenses/{id}` | Удалить трату |
| GET | `/api/users` | Список разрешённых пользователей (для фильтра в панели) |

Валидация на сервере: `amount > 0`, категория из допустимого списка, дата `YYYY-MM-DD`.

## Как работает ИИ-агент

- Tool calling (function calling), а не парсинг текста регулярками.
- Tools: `add_expense`, `list_expenses`, `update_expense`, `delete_expense`.
- `user_id` НЕ является параметром ни одного tool.** Сервер подставляет `user_id` из входящего Telegram-сообщения сам. LLM физически не может указать чужого пользователя — защиты нет даже в JSON-схеме инструментов.
- Категория в JSON-схеме через `enum`: еда, транспорт, жильё, развлечения, здоровье, покупки, другое.
- System prompt содержит текущую дату и день недели (в `APP_TIMEZONE`), чтобы понимать «вчера», «на этой неделе».
- «Последняя трата» = последняя по `created_at` (сортировка `sort=created`, `limit=1`).
- При нескольких кандидатах на удаление/изменение бот переспрашивает пользователя текстом.
- Цикл агента ограничен `maxIterations = 5`. Ошибки LLM и невалидные аргументы tools возвращаются в LLM как `tool result`, чтобы она могла исправиться.
- История диалогов: последние 10 сообщений на пользователя в памяти процесса, под `sync.Mutex`; сообщения одного пользователя обрабатываются последовательно.
- Деньги: рубли с копейками в JSON, в БД хранятся целые копейки (`BIGINT`), без `float`.

## Использование ИИ-ассистента при разработке

- Генерация и правка boilerplate — шаблоны миграций, повторяющиеся CRUD-хендлеры, структуры DTO.
- Поиск информации — сверка сигнатур pgx, поведение Telegram Bot API, формат tool calling у выбранной LLM, нюансы docker compose.
- Уточнение архитектуры — обсуждение границ ExpenseService, где проверять ownerID, как ограничивать цикл агента, как отдавать ошибки LLM обратно в tool result.
- Ревью и подсказки 
- Тесты и проверки — генерация кейсов, подсказки по -race, регулярки для поиска утёкших токенов.
- Генерация моков

Примеры полезных чеков для будущих редакций:

- `gofmt -l .` — проверка форматирования всего кода.
- `go vet ./...` — статический анализ.
- `go build ./...` — сборка всех пакетов.
- `go test ./... -race -count=1` — тесты с race detector.

## Допущения

- Авторизации нет по условию ТЗ. Веб-панель доступна всем. Упомянуто как осознанное допущение.
